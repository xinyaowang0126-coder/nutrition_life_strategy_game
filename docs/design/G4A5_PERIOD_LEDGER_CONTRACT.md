# G4A5：冻结日／周账本契约

2026-10-11。聚合版本`diet-period-v1`。使用既有MealHealthSnapshot，未改变健康档案schema、组成模型或生产开关。

## 写入与只读边界

`DietPatternLedger.append_snapshot(snapshot, config, registry, as_of_date, copies)`只接收确认时冻结的快照。入口复用快照和评估器的校验，拒绝游戏数值、评分/诊断字段及单餐同一原料ID的已知分类冲突；未来模型可作为未知历史保留，不推断其组成。

账本冻结原快照、当时允许的配料事实、餐盘角色、模型/规则版本与依据日期。`day_view`、`week_view`、`get_entries`、`get_snapshots`只返回独立副本，不读取新目录、重新审批、扣费、改库存或写盘。后来更改资料、配置或文案，不改写已冻结历史。读出的营养事实是当时资料支持的记录，不能替代当前指导审核。

同日同餐拒绝重复写入；顺序不限，视图按日期/早午晚排序。日期只允许1–7，合法JSON整数日可规范化使用；缺少完整日期或餐次的旧记录单列，不塞入任何餐次。最多42条，批量`replace_snapshots`先整批检查，失败保留原账本。

## 聚合语义

- `eaten`、`skipped`、`legacy_unknown`与`unrecorded`分别统计。没记到不等于没吃；旧skip标记不升级为当前跳餐事实。
- 每餐角色分别保留，午饭有蔬菜不改变早饭的缺少/未知；无份量相加或“达标”。
- 主要记录配料按ingredient_id去重；同餐复合菜和单品共享ID只计一次，跨餐只增加出现的餐次/日期。同一菜名反复出现不增加配料种数；other、trace、低置信度和unknown不计入已知种数。
- 份量未知独立列出，不抹掉已知组成；缺失资料保留未知，数值是记到的配料数，不是完整饮食总量或健康分。
- 不同模型/规则版本分段，总种数为null，不跨段强行合并。不可识别的未来模型保留未知段。
- 同一段内跨餐同一ID出现分类冲突时，冲突ID排除出种数并明确标注partial；单餐冲突在入口拒绝。
- 无可用组成时计数为null；完整明确跳餐、且无其他未知记录时可为not_applicable/0。未确认、旧或未审不能转成零。
- 原始factor_snapshot保持，因素统计仍not_evaluated；没有抵消、健康评分或新建议生成。

## 展示与本轮范围

`DietPatternPresenter`消费真实账本对象生成事实视图，不接收外部伪造的评估结果。G4MealPreview确认/跳过后才入账，日记增加配料统计；G4RecordPreview是明确标记的七日测试数据查看器，可切日／周、清空和重载。它不模拟游戏存档或正式专业审批。
