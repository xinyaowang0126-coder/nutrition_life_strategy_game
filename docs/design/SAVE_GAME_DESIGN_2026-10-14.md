# 游戏存档与继续游玩方案

日期：2026-10-14。方案已获用户同意，并接入源码及本地Web候选。工程／原生／模型验证已完成，浏览器实际持久化仍待验收，详见[实现记录](../process/GAME_SAVES_2026-10-14.md)。下文保留设计与验收目标，适用于《好好吃饭》人物系列。

## 玩家体验

建议每个故事保留1份自动存档、3份手动存档。学生与周阿姨分别管理，后续新增故事沿用此规则。

- 有进度时，人物卡显示“继续这一周”和“重新开始”；没有进度时显示现有开始入口。重新开始前明确说明将替换该故事的自动进度，手动存档保留。
- 存档卡显示人物／故事、游戏第几天、所处阶段、目标进度与实际保存时间。例如“周慧兰 · 第4天 · 晚餐前 · 排练36/70”。
- 游戏菜单提供“保存进度”“读取进度”“保存并返回故事选择”，同时保留已有餐次记录入口。
- 首版续玩保证恢复最近完成的一次决定。选中但未确认的餐盘可随当前阶段保存；临时悬浮详情、滚动位置和未确认的做饭弹窗不作为继续位置，读档后回到对应选餐页重新确认。
- 离线期间游戏时间不推进，不替玩家吃饭、排练、赴约或结算。冷藏期限依游戏内已记录时间判断，不用现实关闭时长替代。

## 保存时机与事务

自动存档发生在完整决定结束、资源与记录及阶段已全部更新之后：确认餐食／跳餐、执行或跳过行动、明确处理剩菜、确认邀约、夜间安排与日结，以及下一天开场完成。生成菜单后也保存菜单与随机状态。

查看科普、移动鼠标、调整未确认配方不扣料，也不生成完成记录。已确认的决定立即保存，不依赖退出或关闭网页时才写入。保存失败明确显示“尚未保存”，不能误报成功；玩家可重试或导出当前有效进度。

手动保存使用同一份经过校验的完整状态。需要覆盖的槽位先展示原存档摘要；取消保持原文件。保存失败不能破坏上一份可读存档。

## 需要保留的数据

| 数据 | 续玩要求 |
| --- | --- |
| 存档／规则版本、故事与人物身份 | 只接受已支持的故事及兼容版本；不能把校园状态直接当成周阿姨状态 |
| 第几天、阶段、资源与目标 | 保留余额、精力、压力、心情、饱腹、目标、实际参演及结局状态 |
| 当前来源、菜单、选中餐盘、来源菜单缓存、随机状态 | 读取后不重新抽菜单，不通过读档改变未来抽取序列 |
| 当日三餐、行动、时段消耗、次数、组合与周历史 | 不重复扣钱、奖励、补货或生成日结；记录与显示同源 |
| 恢复状态、学习状态、开场是否已执行、日结是否完成 | 不重复应用晨间影响，不把已结算日当成尚未结算 |
| 食材、调味料、熟食批次、批次序号及处置历史 | 保留制作／存放时刻、温度暴露、保存史是否已知、再热次数与原配方；不会因读档清零 |
| 老陈邀约、实际同桌与失约记录 | 计划不能变成完成，已经完成的不能重复执行 |
| 科普触发记录、角色当前偏好、启用范围内的冻结营养档案 | 已有记录不重新用新资料推算；读取不能自行开启健康指导开关 |

现有MealHealthArchive只管理营养档案，不是完整游戏存档。GameRootV2的状态集中，建议新增独立GameSaveStore负责文件与校验，由控制器明确提供捕获／恢复入口；主菜单通过StorySession交接指定故事及存档请求。

存档只包含必要数据，不序列化控件、回调或场景树。恢复前检查故事、版本、字段类型、数值范围、食品／行动身份和阶段关系；全部通过后一次应用并重建界面，不调用正常新开局流程重新扣费或发放库存。64位随机状态采用可精确还原的表达，JSON数值需按字段类型正规化。

## 本地存储与备份

桌面版可用Godot的user://目录保存版本化数据文件；JSON与FileAccess是官方提供的存储方式，项目需要自行定义数据转换和恢复逻辑。[Godot存档文档](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html)

网页版的user://持久化依赖浏览器IndexedDB及其存储许可，隐私模式可能无法持久保存；不能把桌面文件测试当成网页刷新／重开验收。[Godot Web导出文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)

建议提供“导出存档文件／导入存档文件”用于备份和设备转移。本地文件、浏览器存储及导入使用同一格式；导入先校验并预览摘要，再选择存入哪个手动槽位。保留最近一份有效自动备份，采用先写临时文件、确认可读后替换的流程；对旧版本建立明确迁移规则，无法兼容时保留文件并说明原因。

## 必要验证

- 两篇故事从不同餐次、餐后、睡前、日结及结局保存和恢复，确认所有已完成事实一致。
- 中途保存／恢复后推进完整七日，与不中断的同种子路线比较资源、菜单、库存、恢复与结局。
- 冷藏时间、原配方、再热次数、常温不安全批次与未知保存史保持；失败、重复读取不产生额外食物或奖励。
- 邀约计划、真实同桌、失约和参演状态保持，两个故事和手动槽位互不覆盖。
- 损坏文件、不支持的版本、缺失或矛盾字段、写入失败和备份恢复有可理解反馈，不破坏当前进度。
- 实际浏览器刷新、关闭重开、同源新版本、不能持久化的环境及导入导出验证。此前自动浏览器绑定限制仍单独记录，不能以原生或PCK测试替代。
