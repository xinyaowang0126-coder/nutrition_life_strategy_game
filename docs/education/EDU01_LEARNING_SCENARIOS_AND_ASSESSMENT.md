# EDU-01：七日学习场景与验证方案

版本：1.0，2026-10-08。状态：课程设计与任务包完成，尚未接入玩家界面、专业签署或真人试玩。对应[项目目标](../design/PROJECT_GOALS.md)中的L1–L4；参与者只阅读[任务页](EDU01_PARTICIPANT_TASKS.md)，本文件供开发、审校和试玩主持人使用。

## 1. 场景依据与实施范围

复用已有七天、四来源、预算、库存、餐次记录及事件，不增加答题关卡。实际入口为选择来源→选餐→餐后行动→睡眠→日结→新日/结局。事件以[WeeklyEventService](../../life-strategy/scripts/systems/WeeklyEventService.gd)为准：第2天天气放晴、第3天食堂换菜单、第4天外卖券、第5天小测提醒、第6天下雨；不把这些确定事件称为随机新剧情。

下表定义未来G4切片应提供的学习机会。当前健康资料仍全部draft、四个开关关闭，组成预览与观察尚未上线；文案样例用于内部核对，涉及玩家健康解释的内容仍须EDU-02/03及相应NUT审核。题目中的明确配料是给定的模拟事实，不替代生产profile审核。

每个目标至少有一个正常流程入口：L1在选择时，L2在日结与跨日对照，L3在费用/来源比较与下一步，L4在资料状态与游戏效果分区。不能只靠玩家主动打开百科获得学习机会，也不能把拒绝建议或信息不足视为错误选择。

## 3. 首次介绍、反馈与复玩规则

场景表可同时练习多个目标，但首次正式介绍只选一个判断要点；其余能力通过现有价格、库存和记录自然练习，不追加另一层解释。

- 每天至多介绍一个新的判断要点，每次只用一条短句；详细例子和依据由玩家展开。已有新日弹窗仍负责状态与事件，不再增加一层教学弹窗。
- 每餐首层只保留实际组成/资料状态和选择所需费用；日结至多突出一条与真实记录有关的观察，允许无观察态。已看懂的说明不随悬浮、返回、换来源或重新打开弹窗重复播放。
- 同一目标的首次介绍以当次运行内的已展示状态控制；重入不重复触发，不改变费用、库存、健康快照或恢复记录。跨启动是否保留介绍状态另行设计，不把已有健康JSON当作完整存档。
- 复玩默认减少首次介绍，组成、资料状态、费用和结果仍可见；帮助可随时重新打开。复玩中若出现新类型未知或规则变化，只解释当次新增内容。
- 不以知识答对、接受建议或凑齐类别放行确认。正常选择、失败、跳餐和重开均继续按玩法规则处理；教育反馈不奖励“服从”，不影响R2结局条件。
- 提示按“有资料、有相关记录、当前确实可用”触发。缺少代表性食物时不控制抽牌去制造唯一答案；所选资料不足时显示不足，不用旧quality补结论。

## 4. 配对任务设计

任务A/B各4题，每题约1–2分钟，相同目标、信息量和约束，菜单不同。它们是读表和安排任务，不是个体膳食评估；所用数值只描述题目条件，不推算真实摄入目标。

| 目标 | A任务 | B任务 | 等价设计 |
| --- | --- | --- | --- |
| L1 | 米饭、鸡蛋、青菜饭盒 | 面条、豆腐、番茄面盒 | 三种明确组成；同样未提供份量、比例或全天饮食 |
| L2 | 两次没吃早餐、六次同配料鸡肉时蔬饭 | 两次没吃午餐、六次同配料豆腐番茄面 | 三天九个餐次、两次明确没吃、重复配料，均不得按次数虚增种类 |
| L3 | ¥8早餐；食堂组合、便利店、两件存粮 | ¥8早餐；另一组食堂组合、便利店、两件存粮 | 同预算、来源上限、早餐外卖关闭、便利店两项合计¥9；允许多解 |
| L4 | 酸奶添加糖未知、游戏心情+4、喝水记录 | 饭盒钠未知、游戏精力+3、早点睡记录 | 同样检查unknown、游戏效果和独立记录，不能由恢复推出因素消失 |

L3题目限制是给定模拟菜单；不要求与某个随机种子的生产手牌一致。每份答题安排只能使用该题表中可用食物，不得调用未给出的补货、优惠或现金。未来改为游戏内任务时必须重新对接真实来源与手牌API。

## 5. 评分依据：每项0–2，另记关键误解

| 项目 | 2分 | 1分 | 0分或关键误解 |
| --- | --- | --- | --- |
| L1 | 正确说明谷薯/主食、蛋白质来源、蔬菜三类组成，并明确没有份量/全天信息不能判断吃够或整体健康 | 组成基本正确或边界正确，但缺少另一部分 | 无法辨认组成，或明确认为出现三类就代表摄入充足。不能要求逐字使用专业名词 |
| L2 | 说出两次对应餐次没吃，且重复相同配料不会增加原料种类；只讨论记录模式 | 能说出餐次或重复模式之一，无过度推断 | 把同配料重复次数当新增种类；据此诊断疾病/营养缺乏另记关键误解 |
| L3 | 给出合法具体组合与正确支出/库存变化，解释至少一项代价，并指出便利店两项合计¥9超预算 | 合法安排但算账/代价解释不完整；不要求唯一餐盘 | 超预算、用超过库存的数量、超过来源上限或早餐选外卖；“补蔬菜”但没有给定可用项不算可执行安排 |
| L4 | 同时说清未知不等于没有、游戏效果不能证明营养更好、恢复行动不清除用餐资料；能区分两条记录 | 三点中理解一至两点，无明确诊疗或抵消主张 | 以未知当零、以游戏状态排名现实健康，或认为喝水/睡眠清除因素；后两类另记关键误解 |

允许日常语言、多种合法策略，以及明确表示信息不足。L3不按某种食物是否被选来评分。逐项分数是研究记录，不进入HUD、结局、健康档案或玩家排名。

答案核对样例：A3食堂三项¥7、余¥1，消耗出门精力；也可吃宿舍燕麦和牛奶，现金不变但两件各减1。B3食堂三项¥8、余¥0；也可吃宿舍苹果和酸奶，两件各减1。两题便利店面包+牛奶均¥9，不能在¥8内一起买；只买其中一项仍可合法作答。重复消费同一件存粮两份不合法。

学习迁移暂定达标者需L1=2且L3=2；L2/L4另报达标人数和具体误解，不能用某项高分补另一项。沿用[专项理解门](../../life-strategy/docs/plans/nutrition_health_guidance/05_testing_review_and_measurement.md#132-暂定发布门槛)及[项目双重验收](../design/PROJECT_GOALS.md#6-同时验证学习与乐趣)：至少80%迁移达标，同时满足关键理解、可行建议和趣味条件。

## 6. 主持流程与记录模板

1. 使用参与者代号，说明任务可跳过、各题相互独立；不要求提供真实摄入、体重或疾病信息。
2. 交替分配A前测/B后测与B前测/A后测，记录版本与顺序；小样本不保证组间平衡，结果按顺序分别报告。
3. 前测只读题；可以解释表头或操作，不暗示正确答案，不在前后测之间反馈分数。原型游玩中按正常提示推进，记录实际遇到的学习入口和阻塞。
4. 完成一局或自愿停止后做另一套题，按同一评分依据保存原话。原型未开放相应学习入口时记录“未接入”，不能把它当作该入口有效性验证。
5. 后测结束再做中性追问与解释，保留初次答案；引导后的理解单独记，不覆盖后测。重复出现于两人的关键误解进入设计问题清单。
6. 询问5级兴趣并提供无额外奖励的第二局机会，分开记“愿意”“实际开始”“实际完成”和想改的安排；预留时间，时间不足记未观察。

每名参与者复制一份记录：

```text
参与者代号 / 日期 / 候选版本 / 设备：
任务版本 / 前后测顺序：
前测：L1 __ L2 __ L3 __ L4 __；原话与用时：
游玩：实际完成日数 __；L1/L2/L3/L4入口实际遇到情况：
操作卡点 / 阻塞 / 中断原因：
后测：L1 __ L2 __ L3 __ L4 __；原话与用时：
关键误解初次表现 / 中性追问后表现：
兴趣1–5 / 复玩意愿 / 实际开始与完成 / 想改的安排：
跳过或缺失项目及原因：
```

报告给出招募数、完成数、缺失数、每项前后达标人数及配对变化，不把缺失回答算作正确；也不能无声删去中途退出者提高通过率。两轮5–8人用于发现问题，10–15人用于候选验证；前后表现变化只作描述，不能单凭它宣称因果或医学收益。
