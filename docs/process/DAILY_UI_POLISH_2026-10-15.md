# 每日流程打磨：弹层输入与推进

本轮沿人物开局、新日提示、恢复详情、日结和餐次记录继续检查。实际键盘输入发现：上轮共用工作台的键盘处理也被普通早餐来源页继承，能在新日提示背后接走 Enter；旧弹窗的默认继续快捷键还会覆盖“查看详情”的意图。

已修复：

- 只有控制器作为弹层打开的工作台接管模态键盘输入，普通来源页保留正常的页面导航。
- 新日提示、日结、餐次记录和主动打开的详情将 Tab／Shift+Tab 与方向键限制在当前面板，滚动区域跟随焦点。
- Enter 激活当前聚焦的详情、记录或继续按钮；按住按键不会重复执行。恢复详情和食物详情关闭后回到各自入口。
- 日结中 Esc 先收起展开的依据，保持当天和结算记录；餐次记录关闭后回到小结。
- 日结推进请求只发送一次，隐藏弹窗不接受延迟信号；重新显示新日／日结时恢复操作状态。旧日结的离场动画不会关闭随后打开的新小结。

新增 7 项自动化回归，覆盖来源页抢键、详情焦点恢复、详情与继续的 Enter 区分、Esc 收起、隐藏后的延迟输入和连续推进。完整测试 **477/477、42 套**，主场景启动和 Web 导出资源审查通过。

原生实际输入分别检查 640×960 与 1280×720：人物入口和介绍 → Enter 进入首日 → 厨房提醒返回 → 恢复详情的打开／焦点循环／关闭 → 日结详情 → 餐次记录 → 返回小结 → 进入第2天。日结准备明确使用“三餐跳过、行动跳过、早睡”的控制器夹具，不作为完整七日纯键盘验收；所有弹层操作使用真实 InputEventKey。另验证日结重开时旧动画不干扰新内容，并重跑做饭工作台与存档确认的键盘回归。
