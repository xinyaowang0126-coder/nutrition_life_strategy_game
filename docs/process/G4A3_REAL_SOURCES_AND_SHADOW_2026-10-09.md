# G4A3：真实四来源适配与影子验证

2026-10-09。本轮把已有单餐组成、当前加选/替换和冻结日记接口接到真实 V2 选择状态。正式营养输出仍待审校；四个生产开关保持关闭。本轮没有增加玩家界面。

## 完成内容

- `GameRootV2.get_meal_guidance_input()` 返回当日、阶段、来源、当前手牌、已选食物、余额和库存的独立副本。读取不抽牌、不加载健康资料、不写档。
- `MealGuidanceAdapter` 从真实卡池校验食物与餐次，读取价格和来源上限，并应用当前日期的事件。第 4 天外卖配送费为 ¥1，第 6 天为 ¥5；费用只计一次。存粮按库存可用性处理，确认价为 ¥0，现金购买同一食物仍读卡牌价格。
- 候选快照冻结完整的加选/替换组合。建议带当日和上下文 SHA-256 标记；执行前重算并比对完整动作，余额、手牌、选项、阶段、日期、资料或相关库存改变后拒绝旧建议。解析只返回新的选择，扣款和库存消耗仍由原确认流程执行。
- `MealGuidanceShadow` 提供显式开发检查、确认时冻结记录和只读日记检查。已有 data-on 快照优先，不用现有资料重建旧记录；日记拒绝混日、重复餐次、食物或跳餐标记不一致，不补造尚未发生的餐次。

这些模块没有接入正常游戏循环；影子调用由测试或 MCP 显式发起。模拟资料不获得生产批准，未完成自动影子运行、正式候选排序/冷却/下一餐计划、日周聚合或 NUT-308 旧 quality 断开。

## 运行与诊断记录

Godot MCP 初始没有会话，启动现有 4.7.2 编辑器后恢复连接；没有修改签名插件。初次测试有一处 Dictionary 类型推断错误，修正后专项/全量通过。两处临时 `game_eval` 查询分别使用了错误的存粮 Footer 路径、在来源点击未成功时读取空手牌索引，触发调试中断；查询修正并重开隔离局后完成库存核验，最终游戏日志无错误。保留旧 Debugger 记录，未将这些诊断失败记为通过。

部分鼠标点击没有改变选中状态，均按返回状态确认后重试；未把发送成功当作选择成功。食堂最终使用实际鼠标输入，存粮最终使用 live `game_eval` 的正常 V2 命令，两者范围分别记录。1200 像素图片返回有一次传输失败；随后截图元数据及直接保存游戏原始帧成功。

本地验证使用项目内 `APPDATA/LOCALAPPDATA`，避免写入用户编辑器配置。初次隔离 Web 导出缺少无多线程模板，补入现有 4.7.2 模板后又发现沙箱临时路径的 `tmpproject.binary` 写入错误；将 `TEMP/TMP` 指向项目缓存后单独重导出并复用统一 PCK 审计，最终无错误。没有用此前带错误日志的导出作为最终产物。

复现：

```powershell
$env:GODOT_BIN = 'E:\Program\GodotEngine\Godot_v4.7.2-stable_win64_console.exe'
.\tools\verify_project.ps1 -Suite g4_sources
& $env:GODOT_BIN --headless --path life-strategy --script res://tests/g4_sources_probe.gd
.\tools\verify_project.ps1 -ExportWeb -ExportOutput .\artifacts\g4a3-2026-10-09-web
```

缓存日志位于 `.cache/g4a3/`；使用沙箱环境时需要同样设置项目内运行目录与匹配模板。
