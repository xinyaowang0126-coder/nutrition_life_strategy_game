# 完整游戏存档：网页版接口与本地实现

日期：2026-10-14。已按[存档设计](../design/SAVE_GAME_DESIGN_2026-10-14.md)接入源码及本地Web候选，未提交、推送或发布线上Play。浏览器真实持久化验收未完成，下面区分工程、原生与模型证据。

## 玩家入口

- 每个故事1份自动存档、3份手动存档，学生与周阿姨互不覆盖。人物卡有进度时显示“继续这一周”、所处日期／阶段、目标、余额及保存时间；另有重新开始和其他存档入口。
- 游戏菜单保留餐次记录，并提供手动保存、读取、导出、导入与保存后返回故事选择。替换已有或暂不可读取的手动槽位需要明确选择；取消不更改文件。
- 存档恢复游戏数据并重建界面，保留已生成菜单与完整64位随机状态。读档不重复执行开场、吃饭、补货或日结；现实离线时间不推进游戏内日期。
- 当餐未确认的选择可在手动存档中保留，未确认的配方弹窗与悬浮详情不作为续玩位置，恢复后回到对应选餐页。
- 冷藏时刻、温度暴露、原配方、保存史是否已知、再热次数、库存、邀约／实际同桌、真实参演及周历史都进入完整状态。已知记录与未知字段原样保留，不用当前配方重新推算。

## 网页如何保存

GameSaveCodec定义版本化JSON数据并校验故事、人物、资源、阶段、记录类型、恢复状态、批次编号、同桌历史、随机状态与冻结档案。金额／次数正规化为整数，分配到菜肴的非整数调味量保留，64位随机数用十进制字符串保持精度。存档不序列化场景树、控件或回调，也不修改正式健康指导开关。

GameSaveStore在桌面使用文件，在网页版通过Godot JavaScriptBridge调用内置JavaScript接口。网页版使用同源IndexedDB数据库`nutrition-life-strategy-saves`，`slots`存储以故事与槽位为键：`choir_week:auto`、`campus_exam:manual_1`等。首次打开异步读取，完成前不把尚未读取的数据当成没有进度。

每次完整决定／阶段更新后调度自动保存；处理剩菜与确认邀约也会保存。写入请求排队、后台自动保存合并最新状态。只有IndexedDB事务完成才更新缓存并提示“已保存”；出错提示“尚未保存”，已有进度保留。最近一份已验证数据与新数据在同一事务中处理，读取主存档失败时可以回到有效备份。

导出使用浏览器文件下载；导入通过文件选择读取，先检查格式、大小和版本，预览进度并选择槽位，再恢复。桌面提供相应文件对话框。两个平台使用同一数据格式，设备转移通过文件完成。

浏览器存档属于当前网址来源与浏览器本地数据，本地预览与线上网站不会自动共享；清理网站数据、存储限制及隐私浏览可能影响长期保留。此实现未加入账号或云同步。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)、[Godot JavaScriptBridge](https://docs.godotengine.org/en/stable/classes/class_javascriptbridge.html)、[Godot Web导出与持久化](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)
