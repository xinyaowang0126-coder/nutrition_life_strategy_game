# 后续工作方案总览

> 本目录记录第一轮原型评估与拆分方案。当前 V2 UI 的实现状态、收尾优先级和发布验收清单以 [`../UI_REMAKE_PLAN.md`](../UI_REMAKE_PLAN.md) 为准；其中部分“已落地”描述仍对应旧 `GameRoot`，不应作为 V2 完成证明。

这组文档把当前项目的后续工作拆成五条可以独立验收的路线。每份方案都区分了“本轮已落地”和“后续建议”，避免把设想误当成已完成功能。

## 当前判断

项目已经从“可运行的脚本原型”进入“可继续迭代的游戏原型”阶段：七天循环、用餐/行动/睡眠与结局流程能够工作，餐前来源选择已接入，核心结算开始服务化，主界面也开始由可复用 Godot 场景组成。接下来最重要的不是继续堆功能，而是把一次完整游玩打磨得清楚、稳定、有反馈。

## 五条工作路线

1. [玩法与餐前来源](./01_gameplay_and_meal_sources.md)：完善不同来源的策略差异、卡池与经济闭环。
2. [UI 与视觉](./02_ui_and_visual.md)：减少常驻文字，建立场景氛围、卡牌反馈和多分辨率布局。
3. [文案与叙事](./03_copy_and_narrative.md)：统一自然、克制的校园生活口吻，并让数值变化具有生活语境。
4. [Godot 场景架构与测试](./04_godot_scene_architecture_and_testing.md)：继续拆分控制器、数据和视图，用场景、资源、信号与自动化测试支撑迭代。
5. [营养与健康指导能力升级](./nutrition_health_guidance/README.md)：取消误导性总分，建立独立数据与评估层、选择期反馈、可行建议、证据治理和专业审校。

## 建议执行顺序

- 第一阶段：冻结现有行为基线，完成营养总分、抵消暗示等最小安全修正，同时守住餐前来源闭环与关键结算回归。
- 第二阶段：建立营养健康资料和多维评估底座；并行完成通用主流程 UI、背景素材和卡牌交互验收。
- 第三阶段：接入选择期餐盘预览、每日/每周结构记录和可行建议，完成桌面与竖屏验收。
- 第四阶段：通读全部玩家可见文案，补齐内容数据、证据登记、事件与结局差异，并完成营养/标签专业审校。
- 第五阶段：继续拆分 `GameRootV2`，补充跨场景集成、旧存档、组合穷举和发布门验证。

五条路线可以并行制作，但每个可发布版本都应同时通过：一轮完整流程、数值一致性、无报错、多尺寸可操作、玩家可见文本复核；凡涉及营养与健康指导，还必须通过专项方案定义的数据、证据、专业审校与无总分/无抵消发布门。
