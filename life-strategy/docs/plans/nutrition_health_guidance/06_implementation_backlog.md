# 06 实施 Backlog

## 1. 使用方式

本文件是后续逐步实施的唯一任务入口。每个相关 PR：

1. 只选择一个可独立验收的纵向切片；
2. 在 PR 描述引用任务 ID；
3. 回填状态、实际改动文件、测试命令、截图和审校记录；
4. 如改变规则，先更新本目录相应设计文件；
5. 合并后在本文件把任务标为完成。

状态：

- `[ ]` 未开始；
- `[~]` 进行中；
- `[x]` 已完成且验收；
- `[!]` 阻塞，必须写原因和解除条件；
- `[-]` 经决策取消，保留原因。

规模只表示单人开发量：

- XS：约半天；
- S：约 1 天；
- M：约 2–3 天；
- L：超过 3 天，执行前必须再拆。

## 14. 默认产品假设

在用户/团队未另行决定前，执行采用以下保守默认：

- 主角年龄不明确，因此不显示个体化数值目标；
- 健康信息只面向一般教育，不收集现实健康资料；
- 食物按虚构但固定的游戏内产品/配方建模；
- 无可靠配方时使用 unknown；
- 周回顾不影响结局；
- 新营养标签玩法保持关闭，直至法规专业复核；
- 来源池不强求每处都能组成完整餐盘；
- 首要发布范围为饮食结构，饮水/睡眠只做独立记录。

这些假设可以修改，但必须更新总方案决策记录和受影响任务。
